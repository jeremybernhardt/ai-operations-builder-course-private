## Scenario and purpose

An operator-builder supervising AI-generated SQL, Python, dashboards, or automations needs to see what changed, preserve a known-working state, avoid recording credentials, and recover from bounded mistakes. This lesson established that local safety layer before GitHub or the course repository.

## Deliverable

A disposable local-only Git repository with safe sample files, an ignored simulated secret, three commits, an inspected change history, and a verified recovery exercise.

## Verification method

Observed Terminal outputs for paths, environment versions, status, unstaged and staged diffs, commits, history, restore, tracked files, ignored/history checks, and remotes; learner explanations; and a comparable `NOTES.md` change cycle.

## Scope completed

- Mac home and project paths; hidden dotfiles; bounded Terminal navigation.
- Git versus GitHub and local versus remote.
- Working files, staging, commits, `HEAD`, and `main` at a beginner level.
- `git init`, `status`, `add`, `diff`, `diff --staged`, `commit`, `log`, and `restore` in a disposable repository.
- `.gitignore`, `.env`, `.env.example`, and basic secret-handling limitations.
- Comparable challenge and teach-back.
